---

Most of njMule's style is enforced automatically: `cargo fmt` and Clippy guard the Rust engine and
desktop shell, Prettier and `vue-tsc` guard the interface and website, REUSE checks license headers,
and SonarQube Cloud gates quality on pull requests. A few rules no tool catches; this page lists
them all.

## Formatting

Every file type follows `.editorconfig` and `.gitattributes`:

| Rule | Exception |
|---|---|
| 4-space indentation, in Rust, TypeScript, XML, YAML and scripts | tabs in Makefiles only |
| LF line endings, in the repository and in every checkout | `*.cmd` and `*.bat` files use CRLF, which `cmd.exe` needs |
| UTF-8, a final newline, no trailing whitespace | Markdown keeps trailing whitespace |
| Rust, TypeScript: at most 120 columns | Markdown is wrapped at about 100 columns |

- **Rust (`njmule-engine`, `njmule-desktop/src-tauri`, `xtask`)**: formatted with `cargo fmt`
  (`rustfmt.toml`, 120 columns, 4 spaces) and linted with
  `cargo clippy --locked --all-targets -- -D warnings`.
- **Interface and website (`njmule-ui`, `website`)**: formatted with Prettier (120 columns, 4 spaces,
  single quotes, LF), checked by `cargo xtask ui`
  ([Interface](interface.mdx#formatting-and-types)) and `cargo xtask site-check`
  ([Documentation](documentation.mdx#building-the-site)).

## Rust safety and lints

`njmule-engine/Cargo.toml` enforces strict safety defaults on production code:

- `unsafe_code = "forbid"` — the engine contains no `unsafe` blocks;
- `unwrap_used = "deny"`, `expect_used = "deny"`, `panic = "deny"` — untrusted network and file
  input is handled with `Result` / `Option`, never panics;
- `indexing_slicing = "deny"` — use `.get(...)` instead of panicking slice indexing;
- `arithmetic_side_effects = "deny"` — use checked/saturating arithmetic where overflow is possible,
  and release builds keep `overflow-checks = true`.

## Comments

- Comment only what the code cannot say: the *why*, invariants, security reasons, references to a
  specification or an RFC.
- Keep comments to one or two lines. No comments that restate the code, no change history, no
  "added by". The story of a change belongs in its commit message.
- Doc comments: one summary sentence; skip trivial getters or obvious helpers.
- **Never reference eMule's source code** in code, comments, tests or commit messages: no file names
  of its sources (`*.cpp`, `*.h`), no line numbers, classes, functions or variables, no eMule version
  numbers, and no "as eMule does" phrasing. Describe the protocol or the file format itself. Name
  eMule only where the feature is about it: importing an eMule profile, interoperability tests.

## Logging

- Log through `tracing` (`info!`, `warn!`, `debug!`, `error!`) with structured fields or format
  arguments.
- Never log secrets (passwords, API tokens, private keys).
- Keep logged untrusted strings bounded and single-line so peers cannot forge log entries.

## Engineering rules

- **Use what exists.** The standard library or a well-known, maintained crate/library comes before
  a utility, codec, parser or algorithm of your own
  ([Dependencies](dependencies.mdx#choosing-a-library)).
- **The engine knows no desktop UI.** `njmule-engine` runs completely headless; the Vue interface
  and desktop shell communicate with it only through the [remote-control API](api/index.mdx).
- **Hands off the user's eMule.** Never write into an eMule installation or configuration folder:
  the import only reads them.
- **Protocol cryptography.** MD4, MD5, SHA-1 and RC4 appear only where the eD2K and Kad wire
  protocols or file formats mandate them; updates use Ed25519 (minisign), web passwords use PBKDF2,
  and TLS/QUIC use rustls + ring.

## Licensing and REUSE

njMule follows the [REUSE](https://reuse.software) specification, which CI checks on every push.

- Every source and text file starts with the two SPDX lines in its comment syntax, for example in
  Rust or TypeScript:

  ```rust
  // SPDX-FileCopyrightText: 2026 Salvatore Coppola and the njMule contributors
  // SPDX-License-Identifier: GPL-3.0-or-later
  ```

- Files that cannot carry a comment (binaries, JSON, images, lock files, golden fixtures) are
  covered by an entry in [`REUSE.toml`](https://github.com/njMule/njMule/blob/main/REUSE.toml).
  This site's pages are covered there too, under CC BY-SA 4.0.
- Third-party code or assets keep their notices and are recorded in `REUSE.toml` and `NOTICE`; only
  licenses compatible with the GPL 3.0 are allowed ([Dependencies](dependencies.mdx#licenses)).
- **No graphical asset of eMule** (icons, bitmaps, skins, logo) is ever used or derived from: all
  artwork is original and lives in `branding/`.
- **No personal data** in the repository: no copies of an eMule configuration, user hashes, nick
  names, IP addresses or screenshots of your own eMule. Keep them in the git-ignored
  `fixtures-private/` and `.local/` folders.

## UI colours

The interface has one sober palette with pastel tints, the same in the desktop window and in the
web interface, compatible with whichever theme is in use. The default theme is Nord Light or Nord
Dark, following the system's colour scheme; Primer, Cupertino and Dracula stay selectable.

- **Tokens only.** Use the theme's colours (`--color-bg-*`, `--color-fg-*`, `--color-accent-*`,
  `--color-success-*`, …) and njMule's `--nj-*` tokens. The theme's colours are in
  `njmule-ui/src/styles/themes.css`, one rule per theme, converted once from the AtlantaFX 3.0.0
  themes (MIT); the `--nj-*` tokens are in `njmule-ui/src/styles/njmule.css`. Those files hold the
  only colour literals: none in TypeScript, Vue or CSS elsewhere.
- **Every token has a light and a dark value**, and the system's forced colours (high contrast)
  take the place of the tokens while they are on.
- **Pastel for surfaces, theme colours for text.** Pastel tones fill surfaces, bars, charts and
  chips (`*-subtle`, `*-muted`); text uses the theme's `--color-fg-*` and `--color-*-fg` tokens,
  never a pastel tone. Saturated colours are kept for real errors and warnings.
- **Accessibility (WCAG 2.2 AA).** Text keeps a contrast of 4.5:1 at least (3:1 for large text),
  essential icons and graphics 3:1; colour is never the only cue, so add an icon, a tooltip, a
  legend or a pattern.
- **The brand** is a deep blue `#24427A`, an off-white mark `#F4F6FB` and warm orange accents
  `#F5A65B` (see `branding/README.md`). Orange stays an accent, never a large surface.

## The pre-commit hook

An optional Git hook runs `cargo fmt --check` on all three Rust crates before each commit:

```bash
git config core.hooksPath .githooks
```
