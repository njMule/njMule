njMule's engine compiles directly to a standalone native executable (`njmule` / `njmule.exe`) with
Rust and Cargo: users need no runtime installed, startup is instant and memory usage is low. Every
package carries it; the desktop packages add the Tauri desktop window (`njmule-gui`, see
[Building](building.mdx#the-desktop-window)), and the Windows packages add the
[service host](#the-windows-service-host).

## Release engine executable

Build the compressed web interface assets first so the engine embeds them, then compile the release
binary:

<Tabs groupId="os">
<TabItem value="windows" label="Windows" default>

```powershell
.\gradlew.bat :njmule-ui:compress
cargo build --manifest-path njmule-engine/Cargo.toml --locked --release --bin njmule
```

Requires [rustup](https://rustup.rs/) and the Visual Studio 2022 Build Tools (C++ workload). The
executable lands in `njmule-engine/target/release/njmule.exe`.

</TabItem>
<TabItem value="macos" label="macOS">

```bash
./gradlew :njmule-ui:compress
cargo build --manifest-path njmule-engine/Cargo.toml --locked --release --bin njmule
```

Requires `rustup` and the Xcode command line tools (`xcode-select --install`). The executable lands
in `njmule-engine/target/release/njmule`.

</TabItem>
<TabItem value="linux" label="Linux">

```bash
./gradlew :njmule-ui:compress
cargo build --manifest-path njmule-engine/Cargo.toml --locked --release --bin njmule
```

Requires `rustup` and a C toolchain (`build-essential` on Debian/Ubuntu). The executable lands in
`njmule-engine/target/release/njmule`.

</TabItem>
</Tabs>

Try it with `njmule --version` and `njmule --license`.

### Release profile

`njmule-engine/Cargo.toml` configures `[profile.release]` with:

- `overflow-checks = true` — arithmetic overflow panics rather than silently wrapping;
- `lto = "thin"` — cross-crate link-time optimisation with fast builds;
- `strip = "symbols"` — smaller release binaries.

## The static Linux executable

The Synology DSM package, the `linux-x64-static` archive and the `linux/amd64` Docker image use a
fully static x64 Linux executable linked against **musl**, so it runs on distributions with older
glibc (such as Synology DSM) or musl-based systems (such as Alpine):

```bash
sudo apt-get install -y musl-tools
rustup target add x86_64-unknown-linux-musl
./gradlew :njmule-ui:compress
CC_x86_64_unknown_linux_musl=musl-gcc cargo build --manifest-path njmule-engine/Cargo.toml \
    --locked --release --target x86_64-unknown-linux-musl --bin njmule
```

The executable lands in `njmule-engine/target/x86_64-unknown-linux-musl/release/njmule`. Verify
that it has no dynamic library dependencies:

```bash
ldd njmule-engine/target/x86_64-unknown-linux-musl/release/njmule
```

## The Windows service host

On Windows a small C program, compiled with the Visual C++ tools, accompanies `njmule.exe`:

```powershell
.\gradlew.bat nativeService
```

It compiles `packaging/windows/service.c` into `build/windows/njmule-service.exe`: the Windows
service host that runs `njmule.exe` headless once `njmule --service=install` registers the service.
Copy it beside `njmule.exe` to use it.
