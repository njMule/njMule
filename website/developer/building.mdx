njMule's engine is a standalone Rust crate (`njmule-engine`), built and tested with Cargo. The
Gradle Wrapper drives the Vue interface (`njmule-ui`), the Tauri desktop shell (`njmule-desktop`),
this documentation site (`website`), the Windows service host (`nativeService`) and the icon tools.
This page covers local builds and checks; release executables and installers have pages of their own
([Native executables](native-images.mdx), [Packaging](packaging.mdx)).

## Prerequisites

| Tool | Needed for |
|---|---|
| [rustup](https://rustup.rs/) | the Rust engine (`njmule-engine`) and the desktop window (`njmule-desktop/src-tauri`); `rustup` installs the pinned Rust toolchain (`rust-toolchain.toml`) on first use |
| Git | getting the sources |
| JDK 25 (Eclipse Temurin, for example) | Gradle tasks (`njmule-ui`, `njmule-desktop`, `website`, `iconTools`, `nativeService`) |
| Visual Studio 2022 Build Tools, C++ workload | building Rust binaries and `njmule-service.exe` on Windows |
| WebKitGTK 4.1 and GTK 3 headers (`libwebkit2gtk-4.1-dev`, `libgtk-3-dev`, `librsvg2-dev`, `libayatana-appindicator3-dev`, `libxdo-dev` on Debian/Ubuntu) | the desktop window (`:njmule-desktop:shell`) on Linux |
| `musl-tools` and `rustup target add x86_64-unknown-linux-musl` | static Linux / Synology builds ([Native executables](native-images.mdx#the-static-linux-executable)) |
| [WiX](https://wixtoolset.org/) 5.0.2, [nfpm](https://nfpm.goreleaser.com/), Docker | packaging ([Packaging](packaging.mdx)) |

You do not install Gradle or Node.js yourself: the Gradle Wrapper (`gradlew`, `gradlew.bat`)
downloads the pinned Gradle version, and Gradle downloads the pinned Node.js release for the
interface, the desktop shell's Tauri CLI and this site, checked against its SHA-256
([Dependencies](dependencies.mdx)).

## Build and test the engine

From `njmule-engine/`:

```bash
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

This checks formatting, runs Clippy with warnings as errors (production code forbids `unsafe` and
denies `unwrap`, `expect`, `panic`, direct indexing and unchecked arithmetic), and runs all unit,
integration, corpus and black-box flow tests.

To check crate licences, advisories and sources (`deny.toml`), and line coverage:

```bash
cargo deny check
cargo llvm-cov --locked --fail-under-lines 70
```

`cargo llvm-cov` needs `rustup component add llvm-tools` and `cargo install cargo-llvm-cov --locked`.

## Build and test the interface

From the root of your clone:

<TabItem value="unix" label="macOS and Linux">

```bash
./gradlew :njmule-ui:build
```

The rest of this guide writes `./gradlew`; on Windows use `.\gradlew.bat`.

`:njmule-ui:build` generates the API's TypeScript types from `njmule-engine/assets/openapi.yaml`,
type-checks (`vue-tsc`), bundles the Vue app with Vite, runs the Vitest unit tests, checks Prettier
formatting, and produces both the uncompressed desktop bundle (`build/site`) and the gzipped web
interface assets (`build/shipped`) that `njmule-engine` embeds.

### Format the sources

Format before you commit:

- **Rust engine**: `cargo fmt --manifest-path njmule-engine/Cargo.toml`
- **Desktop shell**: `cargo fmt --manifest-path njmule-desktop/src-tauri/Cargo.toml`
- **Interface**: `npm run format` in `njmule-ui/` ([Interface](interface.mdx#formatting-and-types))

## Run from the build

Run the command line and headless engine straight from Cargo:

```bash
cargo run --manifest-path njmule-engine/Cargo.toml -- --help
```

To keep your own settings and downloads out of the way, give it a profile of its own with
`--config-dir`:

```bash
cargo run --manifest-path njmule-engine/Cargo.toml -- --config-dir /home/you/njmule-dev
```

To serve the full web interface from a build, run `./gradlew :njmule-ui:compress` first so
`njmule-engine` embeds the compressed assets from `njmule-ui/build/shipped`. The command-line
options are documented in [Command line](/docs/server/cli).

### The desktop window

The desktop window is a Tauri 2 shell written in Rust in `njmule-desktop/src-tauri`: it starts the
`njmule` executable beside it (which opens a loopback control endpoint) and shows `njmule-ui`. Build
both in release mode:

```bash
./gradlew :njmule-ui:compress :njmule-desktop:shell
cargo build --manifest-path njmule-engine/Cargo.toml --locked --release --bin njmule
```

`:njmule-desktop:shell` builds the interface (`:njmule-ui:site`) and runs `tauri build` with the
Rust toolchain pinned in `njmule-desktop/src-tauri/rust-toolchain.toml`. The window lands in
`njmule-desktop/src-tauri/target/release/njmule-gui` (`njmule-gui.exe` on Windows); copy
`njmule-engine/target/release/njmule` (`njmule.exe` on Windows) next to it, or point `NJMULE_CORE`
at the engine binary, and run it. `--config-dir <folder>` gives it a profile of its own.

Cargo checks the desktop shell as CI does, in `njmule-desktop/src-tauri` once
`./gradlew :njmule-ui:site` has built the interface it embeds:

```bash
cargo fmt --check
cargo clippy --locked --release --all-targets -- -D warnings
cargo test --locked --release
```

## Other tasks

| Command | What it makes |
|---|---|
| `cargo about generate about.hbs -o target/THIRD-PARTY.txt` (in `njmule-engine`) | third-party crate notices shipped with every package |
| `cargo cyclonedx --format json --spec-version 1.6 --describe binaries --no-build-deps --target all` (in `njmule-engine`) | CycloneDX software bill of materials |
| `./gradlew iconTools` | copies the JSVG jar needed by `tools/IconGen.java` into `build/tools` (see `branding/README.md`) |
| `./gradlew nativeService` | the Windows service host `build/windows/njmule-service.exe` ([Native executables](native-images.mdx#the-windows-service-host)) |
| `./gradlew :website:site` | this documentation site ([Documentation](documentation.mdx)) |
