njMule's engine is a standalone Rust crate (`njmule-engine`), built and tested with Cargo. Cargo's
`xtask` helper (`cargo xtask <command>`) orchestrates the Vue interface (`njmule-ui`), the Tauri
desktop shell (`njmule-desktop`), this documentation site (`website`) and the Windows service host.
This page covers local builds and checks; release executables and installers have pages of their own
([Native executables](native-images.mdx), [Packaging](packaging.mdx)).

## Prerequisites

| Tool | Needed for |
|---|---|
| [rustup](https://rustup.rs/) | the Rust engine (`njmule-engine`), the desktop window (`njmule-desktop/src-tauri`) and `cargo xtask`; `rustup` installs the pinned Rust toolchain (`rust-toolchain.toml`) on first use |
| [Node.js](https://nodejs.org/) 24 (LTS) | the Vue interface (`njmule-ui`), the Tauri CLI (`njmule-desktop`) and this documentation site (`website`) |
| Git | getting the sources |
| Visual Studio 2022 Build Tools, C++ workload | building Rust binaries and `njmule-service.exe` on Windows |
| WebKitGTK 4.1 and GTK 3 headers (`libwebkit2gtk-4.1-dev`, `libgtk-3-dev`, `librsvg2-dev`, `libayatana-appindicator3-dev`, `libxdo-dev` on Debian/Ubuntu) | the desktop window (`cargo xtask desktop-shell`) on Linux |
| `musl-tools` and `rustup target add x86_64-unknown-linux-musl` | static Linux / Synology builds ([Native executables](native-images.mdx#the-static-linux-executable)) |
| [WiX](https://wixtoolset.org/) 5.0.2, [nfpm](https://nfpm.goreleaser.com/), Docker | packaging ([Packaging](packaging.mdx)) |

## Build and test the engine

From `njmule-engine/`:

```bash
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked
```

This checks formatting, runs Clippy with warnings as errors (production code forbids `unsafe` and
denies `unwrap`, `expect`, `panic`, direct indexing and unchecked arithmetic), and runs all unit,
integration, corpus and black-box flow tests.

To check crate licences, advisories and sources (`deny.toml`), and line coverage:

```bash
cargo deny check
cargo llvm-cov --locked --fail-under-lines 70
```

`cargo llvm-cov` needs `rustup component add llvm-tools` and `cargo install cargo-llvm-cov --locked`.

## Build and test the interface

From the root of your clone:

```bash
cargo xtask ui
```

`cargo xtask ui` runs `npm ci` (when `node_modules` is absent), generates the API's TypeScript types
from `njmule-engine/assets/openapi.yaml`, type-checks (`vue-tsc`), bundles the Vue app with Vite,
runs the Vitest unit tests, checks Prettier formatting, and builds both the uncompressed desktop
bundle (`njmule-ui/build/site`) and the gzipped web interface assets (`njmule-ui/build/shipped`)
that `njmule-engine` embeds.

### Format the sources

Format before you commit:

- **Rust engine**: `cargo fmt --manifest-path njmule-engine/Cargo.toml`
- **Desktop shell**: `cargo fmt --manifest-path njmule-desktop/src-tauri/Cargo.toml`
- **Cargo xtask**: `cargo fmt --manifest-path xtask/Cargo.toml`
- **Interface**: `npm run format` in `njmule-ui/` ([Interface](interface.mdx#formatting-and-types))

## Run from the build

Run the command line and headless engine straight from Cargo:

```bash
cargo run --manifest-path njmule-engine/Cargo.toml -- --help
```

To keep your own settings and downloads out of the way, give it a profile of its own with
`--config-dir`:

```bash
cargo run --manifest-path njmule-engine/Cargo.toml -- --config-dir /home/you/njmule-dev
```

To serve the full web interface from a build, run `cargo xtask ui-compress` first so `njmule-engine`
embeds the compressed assets from `njmule-ui/build/shipped`. The command-line options are documented
in [Command line](/docs/server/cli).

### The desktop window

The desktop window is a Tauri 2 shell written in Rust in `njmule-desktop/src-tauri`: it starts the
`njmule` executable beside it (which opens a loopback control endpoint) and shows `njmule-ui`. Build
both in release mode:

```bash
cargo xtask ui-compress
cargo xtask desktop-shell
cargo build --manifest-path njmule-engine/Cargo.toml --locked --release --bin njmule
```

`cargo xtask desktop-shell` builds the interface (`ui-site`) and runs `tauri build --no-bundle`
with the version from `VERSION`. The window lands in
`njmule-desktop/src-tauri/target/release/njmule-gui` (`njmule-gui.exe` on Windows); copy
`njmule-engine/target/release/njmule` (`njmule.exe` on Windows) next to it, or point `NJMULE_CORE`
at the engine binary, and run it. `--config-dir <folder>` gives it a profile of its own.

Cargo checks the desktop shell as CI does, in `njmule-desktop/src-tauri` once `cargo xtask ui-site`
has built the interface it embeds:

```bash
cargo fmt --check
cargo clippy --locked --release --all-targets -- -D warnings
cargo test --locked --release
```

## Other tasks

| Command | What it makes |
|---|---|
| `cargo about generate about.hbs -o target/THIRD-PARTY.txt` (in `njmule-engine`) | third-party crate notices shipped with every package |
| `cargo cyclonedx --format json --spec-version 1.6 --describe binaries --no-build-deps --target all` (in `njmule-engine`) | CycloneDX software bill of materials |
| `cargo xtask native-service` | the Windows service host `build/windows/njmule-service.exe` ([Native executables](native-images.mdx#the-windows-service-host)) |
| `cargo xtask site` | this documentation site ([Documentation](documentation.mdx)) |
| `node tools/render-assets.mjs icons branding/njmule-icon.svg branding/generated` | regenerates icons from the master SVG (see `branding/README.md`) |
