This guide is for you if you want to build njMule from its sources, change it, translate it, package
it or drive it from your own programs through its remote-control API. If you only want to use
njMule, the [user guide](/docs/intro) is the place to start.

njMule is a Rust re-implementation of eMule's networks (eD2K and Kad 2), compatible with the eMule
network and licensed under the GPL 3.0 or later. One headless engine (`njmule-engine`) compiles to
a standalone native executable `njmule` that is also the command line and web server. One interface
(`njmule-ui`), written for the browser in Vue 3, drives it only through its remote-control API:
inside the desktop window (`njmule-desktop`, a Tauri 2 shell that starts the engine) and as the web
interface the engine serves.

## Technology stack

| Area | What njMule uses |
|---|---|
| Engine and CLI | Rust (edition 2024, pinned in `njmule-engine/rust-toolchain.toml`), Tokio async runtime, Axum (HTTP server), Quinn + rustls + ring (QUIC / TLS), reqwest (HTTP client), lettre (e-mail notifications), clap (CLI), tracing (logging), jsonschema, minisign-verify, flate2 / lzma-rust2 / tar / zip |
| Remote-control API | an OpenAPI 3.2 document (`njmule-engine/assets/openapi.yaml`), validated against JSON Schema 2020-12 and served by Axum |
| Interface | Vue 3 in TypeScript, built with Vite; Reka UI, TanStack Table and TanStack Virtual; openapi-typescript and openapi-fetch for the API, eventsource-parser for its events; original SVG line icons and the colours of the AtlantaFX themes |
| Desktop window | Tauri 2 in Rust (`njmule-desktop/src-tauri`), with its single-instance, deep-link, dialog, opener, window-state and notification plugins |
| Web interface | Axum inside `njmule-engine`, embedding the gzipped Vue bundle (`rust-embed`), with a login page, sessions and CSRF tokens |
| Native executables | Cargo release builds (`lto = "thin"`, `overflow-checks = true`), static musl builds for Synology/Linux, and a small C service host on Windows (`packaging/windows/service.c`) |
| Build orchestration | Cargo for `njmule-engine` and `njmule-desktop/src-tauri`; Gradle Wrapper for `njmule-ui`, `njmule-desktop`, `website`, `iconTools` and `nativeService` |
| Tests | `cargo test` with `proptest`, golden corpora, and black-box flow + wire-transcript tests for the engine; Vitest with happy-dom for the interface; `cargo test` for the desktop shell |
| Quality gates | `cargo fmt`, Clippy (`-D warnings`, `unsafe_code = "forbid"`), `cargo-deny`, `cargo-llvm-cov`, SonarQube Cloud; Prettier and `vue-tsc` for the interface; REUSE compliance |
| Packages | WiX 5 (Windows MSI), nfpm (deb and rpm), `codesign` and `hdiutil` (macOS), a shell script for the Synology package, Docker |
| Documentation | Docusaurus 3.10 with the OpenAPI docs plugin; screenshots captured from a Rust demo binary with Playwright |

Every dependency is pinned in its lock file (`njmule-engine/Cargo.lock`,
`njmule-desktop/src-tauri/Cargo.lock`, `package-lock.json`, and Gradle's lock files plus
`gradle/verification-metadata.xml`): see [Dependencies](dependencies.mdx).

## Repository layout

| Path | Content |
|---|---|
| `njmule-engine` | the Rust engine, CLI, web interface and remote-control API (`src/`, `assets/`, `tests/`, `examples/web_capture_demo.rs`) |
| `njmule-ui` | the single interface of the desktop window and of the web interface (Vue 3, TypeScript, Vite), with its translations (`i18n/`) and country flags (`flags/`) |
| `njmule-desktop` | the desktop window: a Tauri 2 shell in Rust (`src-tauri/`) that starts `njmule` and shows `njmule-ui` |
| `website` | this documentation site (Docusaurus): `docs/` is the user guide, `developer/` this guide |
| `gradle/` | `libs.versions.toml` (Node.js and JSVG), `verification-metadata.xml` and the Gradle Wrapper |
| `packaging/` | Windows installer (WiX) and service host (`service.c`), Linux packages (nfpm), macOS bundle metadata, Docker image, Synology package |
| `branding/` | original artwork: the master SVG and the PNG, ICO and ICNS files made from it |
| `tools/` | single-file helper programs (icons, flags, translations, update manifest), golden vector generators (`tools/golden/`) and the e2e update server (`tools/e2e-update-server.sh`) |
| `.github/` | the CI, release and documentation workflows, Dependabot, issue and pull request templates |
| `LICENSES/` | the texts of every license used in the repository ([REUSE](https://reuse.software)) |

## Where to start

1. [Build njMule](building.mdx) and run it from the build.
2. Read the [code style](code-style.mdx) and the [testing rules](testing.mdx): every change keeps
   to them, and the build and CI enforce most of them.
3. Read [Contributing](contributing.mdx) before you open a pull request.
4. Pick the page of the area you work on: the [interface](interface.mdx),
   [translations](translations.mdx), [native executables](native-images.mdx),
   [packaging](packaging.mdx), [releases](releases.mdx), [benchmarks](benchmarks.mdx) or this
   [documentation](documentation.mdx).
5. To drive njMule from a script or another program, read the
   [remote-control API](api/index.mdx).
